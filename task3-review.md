## Изменения

- `src/PqDatabase.cpp`: результат попадает в кеш до INSERT; ключ факториала учитывает только первый операнд.
- `src/Application.cpp`: из кеша копируются результат и статус, а не операнды прежнего запроса.
- `src/PqDatabase.h`: конфигурация использует стандартные настройки libpq и переменные PGHOST/PGPORT/PGUSER/PGDATABASE вместо встроенного пароля.
- `src/CalculatorLogger.cpp`: sinks заменены на однопоточные.
- `tests/PqDatabaseTests.cpp`: пять интеграционных тестов — персистентность и ключи, ошибка INSERT, ошибки запросов, ошибка создания таблицы, ошибка подключения.
- `tests/run_postgres.py`: изолированный временный кластер с приватным Unix socket, без TCP; унаследованные PG-настройки исключены. Кластер останавливается и удаляется после прогона. Используется только временная БД.
- `tests/demo_database.sh`: демонстрация заполнения БД через psql с проверкой количества строк.
- `tests/CalculatorTests.cpp`: тест переполнения второго операнда действительно проверяет второй операнд; тест кеша проверяет сохранение порядка текущего запроса.
- `CMakeLists.txt`: опция ENABLE_POSTGRES_TESTS, интеграционные тесты и отдельный Valgrind-прогон libpq; отсутствие Valgrind не создаёт неработоспособный тест.
- `README.md`: настройка PostgreSQL, тесты, демонстрация и команды Perf.

## Проверки

```bash
cmake -S . -B build -DENABLE_POSTGRES_TESTS=ON
cmake --build build -j2
ctest --test-dir build --output-on-failure
python3 tests/run_postgres.py /usr/lib/postgresql/16/bin bash tests/demo_database.sh /home/rio/calculator/build/calculator
```

Сборка успешна. Все 7 проверок CTest прошли: 19 unit-тестов, 5 интеграционных тестов, оба набора также прогнаны под Valgrind. Valgrind не обнаружил ошибок. Локальный журнал: `build/Testing/Temporary/LastTest.log` (перезаписывается последующими запусками).

Демонстрация psql прошла: первая операция создала строку с результатом 5 и статусом 0, переставленные операнды не добавили строку, деление на ноль добавило вторую строку со статусом 7. Пользовательская БД не изменялась.
